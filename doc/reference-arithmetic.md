# The reference arithmetic

## The result

`BigInt` is a non-negative integer held as little-endian 64-bit limbs, $x = \sum_i x_i \beta^i$ with $\beta = 2^{64}$, with no high zero limb, so every value has exactly one representation and zero has no limbs. It is written for clarity first: it is the arithmetic every faster engine is checked against, so it has to be simple enough to be obviously right.

**Folding modulo $M_p$.** For $p \ge 1$ and $x \ge 0$, replacing $x$ by $(x \bmod 2^p) + \lfloor x / 2^p \rfloor$ while $x$ has more than $p$ bits ends with $x \le M_p$ and $x$ unchanged modulo $M_p$; mapping $M_p$ to 0 then gives $x \bmod M_p$, fully reduced in $[0, M_p)$. For $x < 2^{2p}$ it takes at most two folds.

**Res64.** The Res64 of $x$ modulo $M_p$ is the low 64 bits of the fully reduced residue $x \bmod M_p$, printed as 16 uppercase hexadecimal digits, zero-padded. It is 0 for $x = 0$ and for $x = M_p$.

**Products and squares.** The schoolbook product, one row of limb products per limb of one operand, is exact, and so is the symmetric schoolbook square, which forms each cross product $a_i a_j$ with $i < j$ once and doubles their sum. Split at $k$ limbs, $a = a_1 B + a_0$ and $b = b_1 B + b_0$ with $B = \beta^k$, Karatsuba's identity $ab = z_2 B^2 + z_1 B + z_0$ holds with $z_0 = a_0 b_0$, $z_2 = a_1 b_1$ and $z_1 = (a_0 + a_1)(b_0 + b_1) - z_0 - z_2 = a_0 b_1 + a_1 b_0$, which is never negative; for a square, $z_1 = (a_0 + a_1)^2 - a_0^2 - a_1^2 = 2 a_0 a_1$. Split at half the longer operand, rounded up, and handed to the schoolbook form below 4 limbs, the recursion ends.

**Division, reduction and powers.** For $m \ge 1$, long division gives the one pair $q$, $r$ with $x = qm + r$ and $0 \le r < m$, so $x \bmod m = r$ is fully reduced. With the divisor shifted until its top limb has its top bit set, each quotient digit estimated from the remainder's top two limbs over the divisor's top limb, and clamped to $\beta - 1$, is never below the digit, and <!-- cited -->at most two above it, so at most two add-backs correct it ([BrentZimmermannMCA2010, Theorem 1.4.1](references.md#brentzimmermannmca2010))<!-- /cited -->. Left-to-right binary exponentiation, reducing after every product, gives $a^e \bmod m$ in $[0, m)$; $a^0 \bmod m$ is 1 for $m > 1$, and every power is 0 modulo 1.

**The canonical strings.** The canonical hexadecimal string of a value is its digits `0` to `9` and `A` to `F`, uppercase like Res64, with no prefix and no leading zero, and `0` for zero; the canonical decimal string is its digits `0` to `9`, with no sign and no leading zero, and `0` for zero. Parsing accepts a nonempty string of digits of the base, leading zeros and, in hexadecimal, either case included, and rejects everything else as an error: the empty string, a sign, whitespace anywhere, a `0x` prefix, a `_` separator, a non-ASCII digit and any other character. So printing a value and parsing the string gives the value back, and parsing any accepted string and printing it gives the canonical form. Decimal input reads the digits in chunks, as many as a limb always holds, into the value one limb-sized step at a time, and decimal output splits the value by powers of the chunk base that square up from the bottom, divide and conquer.

## Proof

### Folding modulo $M_p$ (the project's own derivation)

Write $x = h 2^p + l$ with $l = x \bmod 2^p$ and $h = \lfloor x / 2^p \rfloor$. Since $2^p = M_p + 1$, $x = h M_p + (h + l)$, so the fold $x \mapsto h + l$ keeps $x$ modulo $M_p$ and lowers it by exactly $h M_p$.

*Termination at $x \le M_p$.* While $x$ has more than $p$ bits, $x \ge 2^p$, so $h \ge 1$ and the fold lowers $x$ by at least $M_p \ge 1$: the loop ends. It ends at the first $x$ with at most $p$ bits, that is $x \le 2^p - 1 = M_p$. It never stops strictly between $M_p$ and $2^p$, since no integer lies there. If $x = M_p$, the residue is 0; otherwise $x < M_p$ is the residue itself. $M_p$ is the one value of at most $p$ bits with all $p$ of them set, which is how the last step recognizes it.

*At most two folds below $2^{2p}$.* If $x < 2^{2p}$ then $h \le 2^p - 1$ and $l \le 2^p - 1$, so after one fold $x \le 2^{p+1} - 2$. If that still has more than $p$ bits, then $2^p \le x \le 2^{p+1} - 2$, so $h = 1$ and $l \le 2^p - 2$, and the second fold gives $x = l + 1 \le M_p$. Squaring a residue gives at most $(M_p - 1)^2 < 2^{2p}$, so a reduction after each squaring folds at most twice.

The fold is reduction modulo a special modulus of the form $\beta^n \pm 1$ written in base 2 rather than base $\beta$, the case [BrentZimmermannMCA2010, § 2.4.4](references.md#brentzimmermannmca2010) treats; the argument above is written out from division with remainder.

### Res64

Res64 is the low limb of the folded residue, $(x \bmod M_p) \bmod 2^{64}$, and 0 when the residue is 0, which covers $x = 0$ and $x = M_p$. For $p < 64$ the residue has one limb and Res64 is the whole residue. <!-- check: 2**64 % mersenne(127) == 2**64 and res64(2**64 % mersenne(127)) == 0 -->For $p = 127$, $x = 2^{64}$ is already reduced, and its Res64 is 0: Res64 keeps only the low limb, so it can be 0 when the residue is not<!-- /check -->. <!-- cited -->This is the residue GIMPS records for a Lucas–Lehmer test, the low-order 64 bits of the final value $s_{p-2}$ ([GIMPSMath, Section Double-Checking](references.md#gimpsmath))<!-- /cited -->, taken here after the full reduction, so a run that ends at $M_p$ rather than 0 gives the same Res64. It is printed as 16 uppercase hexadecimal digits, zero-padded, the form the result line uses.

### Schoolbook

Row $i$ adds $a_i b \beta^i$ into the result, limb by limb with a carry, so after the last row the result holds $\sum_i a_i b \beta^i = ab$, and an $m$-limb times an $n$-limb value fits its $m + n$ limbs. Each step forms $a_i b_j + r + c$, with the result limb $r$ and the carry $c$ at most $\beta - 1$ like the limbs, so the double-width sum is at most $(\beta - 1)^2 + 2(\beta - 1) = \beta^2 - 1$: it never overflows, and its high limb, the next carry, is again at most $\beta - 1$. The carry left when a row ends is its top limb, stored above the row ([BrentZimmermannMCA2010, § 1.3.1, Algorithm 1.2](references.md#brentzimmermannmca2010)).

The square uses $a^2 = 2 \sum_{i < j} a_i a_j \beta^{i+j} + \sum_i a_i^2 \beta^{2i}$. The cross products are summed by the same rows, each row $i$ starting at $j = i + 1$; the sum is doubled by a one-bit shift of the whole number, so the bit carried out of each limb moves into the next, and the diagonal is added. That forms about half the limb products of the general product ([BrentZimmermannMCA2010, § 1.3.6](references.md#brentzimmermannmca2010)).

### Karatsuba

With $a_0, b_0 < B$, $ab = a_1 b_1 B^2 + (a_0 b_1 + a_1 b_0) B + a_0 b_0$, and $(a_0 + a_1)(b_0 + b_1) = a_0 b_0 + a_1 b_1 + (a_0 b_1 + a_1 b_0)$, so $z_1 = (a_0 + a_1)(b_0 + b_1) - z_0 - z_2 = a_0 b_1 + a_1 b_0$, a sum of products of non-negative numbers: neither subtraction goes below zero. With $b = a$ it is $2 a_0 a_1$. This is the additive variant of [KaratsubaOfman1962](references.md#karatsubaofman1962)'s method, which [BrentZimmermannMCA2010, § 1.3.2](references.md#brentzimmermannmca2010) states beside the subtractive variant it presents; the subtractive one avoids the carry limb of $a_0 + a_1$ but needs signs, and the additive one keeps every intermediate value non-negative, as `BigInt` is. The identity holds for every $k$. The split takes $k = \lceil n/2 \rceil$ for an $n$-limb longer operand, so a shorter operand of at most $k$ limbs has $b_1 = 0$.

*Termination.* For a cutoff $c$, the recursion hands the product to the schoolbook form when the shorter operand has fewer than $\max(c, 4)$ limbs. Otherwise the longer operand has $n \ge 4$ limbs, and every operand of the three products has at most $k + 1$ limbs: $a_0$ and $b_0$ at most $k$, $a_1$ and $b_1$ at most $n - k \le k$, and $a_0 + a_1$ at most $k + 1$ with its carry. Since $\lceil n/2 \rceil + 1 < n$ for $n \ge 4$, every call's longer operand is shorter than its caller's, so the recursion ends. <!-- check: (3 + 1) // 2 + 1 == 3 -->At 3 limbs it would not, since $\lceil 3/2 \rceil + 1 = 3$<!-- /check -->.

*The threshold.* <!-- cited -->The best threshold between the schoolbook product and Karatsuba's varies from about 10 to about 100 words with the processor and the relative cost of multiplication and addition ([BrentZimmermannMCA2010, § 1.3.2](references.md#brentzimmermannmca2010))<!-- /cited -->. Here the threshold is a design parameter of the code, not a result of this note: the project set it from a measurement on this code, in the build the checks use, and its value is `KARATSUBA_THRESHOLD` in `src/mp.hpp`. The dispatchers use Karatsuba from that many limbs in the shorter operand and the schoolbook forms below. The proof above holds for every cutoff, so the value bears on speed, not on any result.

### Division

*Normalization.* Shifting both $x$ and $m$ left by $s$ bits, $x 2^s = q (m 2^s) + r 2^s$ with $0 \le r 2^s < m 2^s$, so the quotient is unchanged and the remainder comes out scaled by $2^s$, its low $s$ bits zero; a right shift by $s$ recovers $r$. Choosing $s$ as the leading zeros of $m$'s top limb gives a divisor $B = \sum_{i < n} b_i \beta^i$ whose top limb has $b_{n-1} \ge \beta / 2$.

*The digits.* The quotient comes a limb at a time from the top. Before each step the remainder's window $A$, read from limb $j$ up, is below $\beta B$, so its digit $q_j = \lfloor A / B \rfloor$ fits a limb. Let $t = a_{n} \beta + a_{n-1}$ be the window's top two limbs. Since $A < (t + 1) \beta^{n-1}$ and $B \ge b_{n-1} \beta^{n-1}$, $q_j < (t + 1) / b_{n-1}$, so $q_j b_{n-1} \le t$ and the estimate $q^* = \lfloor t / b_{n-1} \rfloor$ is never below the digit; clamping it to $\beta - 1$ keeps that, since the digit fits a limb. <!-- cited -->With the divisor normalized, the estimate is at most two above the digit, so the correction below adds back at most twice ([BrentZimmermannMCA2010, Theorem 1.4.1](references.md#brentzimmermannmca2010), which cites [Knuth1997, § 4.3.1](references.md#knuth1997) for it)<!-- /cited -->. So subtracting $q^* B$ from the window and, while the result is below zero, lowering the digit by one and adding $B$ back leaves the digit and a remainder $0 \le A - q_j B < B$, which with the next limb below it is again a window below $\beta B$. This is [BrentZimmermannMCA2010, § 1.4.1, Algorithm 1.6](references.md#brentzimmermannmca2010). With a one-limb divisor the window is $t$ itself and the estimate is the digit, which is short division.

Both paths are rare on random operands, so the vectors hold a division that takes each, and one where an estimate refined with the divisor's second limb, the more accurate partial quotient of [BrentZimmermannMCA2010, Exercise 1.20](references.md#brentzimmermannmca2010), is still too large and needs its add-back.

### Powers

Let $e$ have $k$ bits, the top one set, and let $r_i = a^{\lfloor e / 2^i \rfloor} \bmod m$. Then $r_{k-1} = a \bmod m$, and since $\lfloor e / 2^i \rfloor = 2 \lfloor e / 2^{i+1} \rfloor + e_i$ for the bit $e_i$, $r_i = r_{i+1}^2 a^{e_i} \bmod m$: square, and multiply by $a$ for a one bit, reducing after each product, which keeps the congruence. So $r_0 = a^e \bmod m$, with $0 \le r_0 < m$ ([BrentZimmermannMCA2010, § 2.6.1, Algorithm 2.12](references.md#brentzimmermannmca2010)). The algorithm needs a top bit, so $e = 0$ is taken first, and gives $a^0 = 1$, which is fully reduced for $m > 1$; modulo 1 every residue is 0, so $m = 1$ is taken before it.

<!-- check: 13 == 8 + 4 + 1 and 3**2 * 3 % 7 == 6 and 6**2 % 7 == 1 and 1**2 * 3 == 3 and 3**13 % 7 == 3 -->For $3^{13} \bmod 7$, with $13 = 8 + 4 + 1$: from 3, the next bit, a one, gives $3^2 \cdot 3 \bmod 7 = 6$, the zero bit gives $6^2 \bmod 7 = 1$, and the last bit, a one, gives $1^2 \cdot 3 = 3$, which is $3^{13} \bmod 7$<!-- /check -->.

### Radix conversion

<!-- check: 10**19 < 2**64 and 2**64 < 10**20 -->A chunk of 19 decimal digits fits a limb, since $10^{19} < 2^{64} < 10^{20}$<!-- /check -->. Decimal input reads the digits in such chunks from the top, the first chunk shorter when the length is not a whole number of chunks, and sets $x \leftarrow x \cdot 10^{19} + c$ for each chunk $c$: Horner's rule in base $10^{19}$, one limb times the value per step ([BrentZimmermannMCA2010, § 1.7.1, Algorithm 1.23](references.md#brentzimmermannmca2010)). Every character is checked before a value is built, so a bad character anywhere is an error.

Decimal output divides and conquers ([BrentZimmermannMCA2010, § 1.7.2, Algorithm 1.26](references.md#brentzimmermannmca2010)). Let $P_0 = 10^{19}$ and $P_{i+1} = P_i^2$, so $P_i = 10^{19 \cdot 2^i}$, squared up to the first $P_k$ whose square exceeds $x$. For $x < P_k^2$, dividing by $P_k$ gives $x = h P_k + l$ with $h, l < P_k = P_{k-1}^2$. Since $l < 10^{19 \cdot 2^k}$, the digits of $x$ are those of $h$ followed by those of $l$ padded with leading zeros to exactly $19 \cdot 2^k$ digits, and each part is printed the same way one level down, the low part always padded. <!-- check: 10**19 * 10**19 == 10**38 -->At the bottom, $x < 10^{38}$, and one division by $10^{19}$ leaves two limbs to print<!-- /check -->. A power of $b$ bits squares to at least $2b - 1$ bits, so the last power is not squared when that is longer than $x$. <!-- check: (5 * 10**19 + 7) // 10**19 == 5 and (5 * 10**19 + 7) % 10**19 == 7 and 5 * 10**19 + 7 == 50000000000000000007 -->For example, $5 \cdot 10^{19} + 7 = 50000000000000000007$ splits by $10^{19}$ into 5 and 7, and the low part prints padded to 19 digits, 0000000000000000007, after the 5<!-- /check -->. The quadratic alternative, one division by $10^{19}$ per chunk, divides the whole value each time; here most of the work is a few long divisions of halves by halves.

## What mps uses

`src/mp.cpp` holds `BigInt` and its operations as free functions: comparison, sums, differences and shifts by limbs and bits. `reduce_mersenne` folds modulo $M_p$ as proved above, `res64` is the low limb of its result, and `hex64` prints it, the same text the result line prints. `to_hex` and `from_hex` convert to and from the canonical hexadecimal string. `multiply_schoolbook` and `square_schoolbook` are the schoolbook product and the symmetric schoolbook square, `multiply_karatsuba` and `square_karatsuba` the additive Karatsuba recursion down to a cutoff, and `multiply` and `square` choose between them at `KARATSUBA_THRESHOLD`. `divide` is the long division above, short division for a one-limb divisor, `reduce` takes its remainder, and `power_mod` is the left-to-right binary powers, reducing with `reduce`. `to_decimal` prints the canonical decimal string by divide and conquer, through `divide`, and `from_decimal` reads one in chunks.

`src/reference.cpp` holds the two reference tests built on these operations, for odd $p \ge 3$, the domain of both theorems; any other $p$ is an error. `reference::lucas_lehmer` returns $s_{p-2} \bmod M_p$ from $s_0 = 4$, squaring with `square` and folding with `reduce_mersenne` each step ([the Lucas–Lehmer note](lucas-lehmer.md)). `reference::prp3` returns the type-1 residue $3^{M_p - 1} \bmod M_p$, by $p - 1$ squarings from 3, each of the first $p - 2$ followed by a multiplication by 3, folding after each ([the PRP note](prp-and-gerbicz.md)). They return residues and decide nothing: `make check` runs them, on the published Mersenne prime exponents, where they must end in 0 and 1, and on prime exponents whose $M_p$ is composite, against residues Python's integers computed. Nothing in `mps -t` calls them.

Everything here is checked in `make check` against vectors Python's integers computed, committed under `tests/vectors/` with the command that reproduces each file.

## Provenance

The folding proof, its two-fold bound and the recognition of $M_p$ are the project's own derivation, from division with remainder, with [BrentZimmermannMCA2010](references.md#brentzimmermannmca2010) as the context for special moduli. The definition of Res64 follows [GIMPSMath](references.md#gimpsmath). The schoolbook product and square and Karatsuba's identity are textbook, written from [BrentZimmermannMCA2010](references.md#brentzimmermannmca2010) and [KaratsubaOfman1962](references.md#karatsubaofman1962); the bound on the double-width sum, the termination of the recursion at 4 limbs and the choice of the threshold, which the project measured on this code when it set the value, are the project's own. Long division, the binary powers and both radix conversions are textbook too, written from [BrentZimmermannMCA2010](references.md#brentzimmermannmca2010), which cites [Knuth1997](references.md#knuth1997) for the bound on long division's estimate; the short argument that the estimate is never too small, the padding of the low parts and the stopping rule for the powers are written out here. Nothing here is drawn from another program.
